# 图文审核卡规则

图文审核卡解决的是“用户能否一眼看懂每个镜头要拍什么”，不是替代导演母版，也不是提前替模型绑定参考图。

## 1. 固定版式

- 一镜一行。
- 左侧：一张最匹配的现有缩略图；点击可查看原图。
- 右侧：镜号加最少够判断的镜头解释。
- 图片与文字保持明显的左右结构，不把多镜说明堆在一段里。
- 默认缩略图宽约 120～160px、单图通常不超过约15KB；优先使用压缩后的渐进式 JPEG 或 WebP，避免 Markdown 打开过慢。
- 单镜对应单图时默认使用 [舒服版规则](comfortable-review-layout.md) 及 `../templates/visual-review-card-comfortable.html`。用户已认可该视觉基线，直接复用，不自行换成大图墙、多栏参数表或视频段三栏卡。用户明确只要 Markdown 时再使用 Markdown。

### 视频段多图核对的方案 A（不用于默认逐镜审核）

只有核对一个视频段的多张绑定图时，每个视频段才使用同一行内的三栏 CSS Grid：

```text
窄色带（段号／镜号范围／推进）｜绑定图小网格｜意境＋逐镜画面／台词＋收尾
```

- 色带只承担导航，不重复右栏剧情。
- 绑定图使用 2～3 列小网格；五张图排成 3+2，避免末行单图造成大块空白。
- 右栏文字字号大于图片说明；镜号、画面、台词同一横向阅读路径。
- 左右栏由同一个外层 Grid 对齐，禁止依靠 Markdown 空行、浮动或自然换行。
- 页面最大宽度约 1440～1560px；桌面优先，窄屏再纵向堆叠。
- 图片点击打开原图，使用相对路径；页面不依赖服务器、外链字体或 JavaScript。
- 不展示素材职责、哈希、批准状态和后台选择理由。
- 不为填满版面硬塞图片；无准确图的镜头只保留右栏文字。
- 顶部只保留标题、版本、少量全局拍摄约束和视频段跳转，避免工具栏化。

## 2. 用户实际审核什么

默认逐镜舒服版依次显示：镜号和标题、必要摄影说明、画面动作、逐人台词、必要声音。台词用细竖线和说话人加粗突出，设备与声音降为小字号。无对应图时留空。具体样式参数以舒服版模板为准。

视频段多图模式只暴露：

1. 该段绑定图片的小图条；
2. 一句意境或情绪方向；
3. 逐镜的画面与台词；
4. 必要时一句收尾状态。

素材职责、SHA-256、批准状态和选择理由属于后台生成计划，不进入用户审核卡；除非存在候选风险需要用户决定，才用一句短提醒放在卡外。

### 逐镜文字

按需要取用，不强行填满：

```text
镜号　主体／景别；有意义的机位或构图。
动作 + 可见表情 + 情绪落点。
台词（有则保留，并注明必要语气）。
```

普通平视、默认轻手持、重复空间信息和提示词级光效不写。一个完整意思尽量写成一句自然中文，不切成机械短句。

## 3. 图片匹配门禁

图片至少要在以下关键项上不冲突：

- 人物身份与人数；
- 坐／站／走等身体状态；
- 核心动作与道具状态；
- 人物左右、前后和视线关系；
- 日／夜及明显光线状态；
- 镜头需要严格锁定时的景别和构图。

只有氛围接近、但站姿、动作、位置或剧情状态错误的图，不算对应图。找不到准确图片时左栏写 `—`，右栏照常写清镜头；不得为了版面完整硬加。

## 4. 审核图与绑定图分离

图文审核卡中的图片默认标记为 `仅审核`。用户通过后，才按视频生成单元重新判断是否实际绑定。以下状态保存在后台计划，不在用户审核卡里铺开：

| 状态 | 含义 |
|---|---|
| 绑定 | 本视频段实际交给模型，并记录单一职责 |
| 仅审核 | 只帮助用户理解镜头，不交给模型 |
| 不使用 | 已确认构图、动作、状态或身份不适合 |
| 缺口 | 当前没有，但对锁定生成结果确有必要 |

同一审核图不因出现在卡里而自动成为首帧、关系锚点或环境母图。绑定表必须重新给出文件路径、职责、选择理由和批准状态。

## 5. 快速检查

- 每个导演镜号恰好出现一次；
- 图片与镜号语义一致；
- 无图镜头明确留空；
- 右侧文字不重复图片已经清楚表达的信息；
- 卡片只负责审核理解，不展示后台职责／状态表，不写平台图片编号、不连线、不运行模型。
- 静态 HTML 中每个本地图片链接都必须存在；交付前机械检查段数、镜号数、链接数和缺失路径，并至少做一次桌面视口截图验收。
