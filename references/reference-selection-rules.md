# 参考图选择规则

本阶段只决定“该用什么图、为什么”，不写最终提示词，也不执行平台绑定。

参考图选择不是切分后的附属步骤。进入单元切分前，先为连续镜头建立参考图包；相邻镜头能够共用同一环境／机位母图、主要角色集合、关键道具／VFX 和关系锚点模式时，默认优先合并，再用时长与动作负载检查是否需要拆开。

## 1. 先判断生成模式需求

对每个视频单元先选择需求类型：

| 需求 | 适用情况 | 不适用情况 |
|---|---|---|
| 通用参考资产 | 需要锁身份、空间、道具或 VFX，但不要求开场构图完全一致 | 把角色设定板当作具体首帧 |
| 专用起始关键帧 | 开场站位、构图、视线、轴线或动作起点必须精确 | 当成整场通用资产重复上传 |
| 机位关系锚点 | 新半空间、反打或多人关系需要锁定画面左右、深度和视线 | 用环境母图代替具体人物关系 |
| 首尾帧 | 终点状态必须准确，首尾处于同一空间和可连续动作路径 | 跨地点、跨现实层、强行完成正反空间切换 |
| 上段末帧续接 | 延长同一镜头或同一连续动作 | 把末帧当成跨单元连续性的唯一保证 |
| 无关键帧 | 现有角色/环境资产和文字动作足够，构图不需精确锁定 | 关键站位或复杂结果必须被严格控制 |

首尾帧、多参考图和可用数量都是模型能力，不是通用常量。指定模型后必须查询当前官方文档或平台 schema；无法验证时写 `待模型校准`。

## 2. 各类资产只承担一个主要职责

### 角色设定图

负责身份、年龄、发型、服装和体型。设定板或白底图不能自动提供正确空间、动作和开场构图。

### 环境母图

负责空间拓扑、家具位置、光线方向和基础氛围。带人物和具体姿势的画面通常是专用关键帧，不应升级为通用环境母图。

正反环境母图用于不同空间方向时，原则上分配到不同单元；不要同时上传后让模型自行猜何时换机位。

### 道具／VFX 图

只锁关键物件外形或特效拓扑。只有当道具/VFX 对剧情识别重要或曾发生明显漂移时才加入，避免把普通背景物件全部列为参考。

### 专用起始关键帧

应准确包含：

- 开场主体和人数；
- 人物左右与前后关系；
- 正确景别、角度和视线；
- 动作开始前或刚启动的状态；
- 正确空间、光线和美术风格。

图片必须清晰、无明显手脸错误、无冲突文字水印，也不能带有与目标动作相反的强运动模糊、尘土方向或姿势暗示。图生视频模型会继承输入图的构图、主体、光线和风格，错误也可能被放大。

### 机位关系锚点

角色设定图只锁身份，环境母图只锁空间；两者都不能自动锁定具体机位下的人物左右、深度和视线。新半空间、反打或复杂多人关系需要精确时，建议补一张该机位的关系锚点，审核通过后再派生近景。人物实际同侧时，不用过肩或前景肩膀制造错误对置关系。

### 尾帧／首尾帧

只有以下条件同时成立才建议：

1. 结束状态对叙事或剪接必须精确；
2. 首尾帧属于同一世界、相容的美术和画幅；
3. 人物身份、服装、空间方向和道具状态相容；
4. 中间存在合理、可生成的运动路径；
5. 目标模型当前明确支持。

可用于：明确的动作落点、结果揭示、同场景匹配动作、循环或需要精确接下一段的 pickup。不要用于空间瞬移或相互矛盾的正反构图。

### 上一段末帧

从上一视频提取稳定、清晰、没有变形和运动模糊的末端画面，适合延长同一动作。共享一帧只能减少视觉跳变；跨单元仍需动作、声音、视线、遮挡或结果接缝，并在剪辑时处理重复帧。

## 3. 资产选择与状态

优先顺序：

```text
已批准正式资产 → 已批准连续性母图 → 本镜专用关键帧 → 待用户批准候选
```

每个引用项记录：

- 资产 ID 或稳定名称；
- 文件路径；
- SHA-256（文件存在时）；
- `identity / environment / relationship_anchor / prop / vfx / first_frame / last_frame / carryover_frame`；
- 只负责什么；
- 为什么本单元需要；
- 批准状态。

未知状态不得猜成批准。候选图只能写 `待用户批准候选`，缺失则写 `资产缺口`。

如果现有角色、环境、道具和 VFX 已足够，默认不新增静态关键帧。只有开场构图、空间关系、动作起点/终点必须精确，或多次生成失败指向同一视觉锚点缺失时，才建议补图。

普通竖屏一至两名主要人物的镜头，优先使用环境母图＋角色图＋明确的左右／前后／进入／离开语言。不要仅因传统镜头切换、景别变化或短暂反应镜头就新增关系锚点或拆成新生成单元。

## 4. 与下游的边界

本 Skill 输出稳定语义职责，例如 `角色甲身份`、`主场景空间`、`关键道具外形`、`单元A起始站位`。

它不负责：

- 最终提示词中的引用语句；
- LibTV `{{Image N}}` 或其他平台 Token；
- 上传、连线、节点顺序和 `imageListOrder`；
- 模型提交和生成。

这些编号只有在真实平台连线并回读最终顺序后才可信，应由提示词编译和 `libtv-skill` 完成。

## 4.1 审核卡到绑定表

图文审核卡中的图片默认只是 `仅审核`，不能整批照搬进模型。逐视频段重新判断并标注：

- `绑定`：确实需要进入该视频段；
- `仅审核`：只帮助用户理解镜头；
- `不使用`：与本段构图、动作、状态或人物不符；
- `缺口`：对生成控制有必要，但当前没有准确图片。

没有准确对应图时宁可保留文字控制和缺口，也不要用相似旧图误导模型。绑定表按视频段列出图片、单一职责、路径、哈希、理由和资产批准状态。
