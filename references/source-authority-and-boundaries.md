# 源稿权威、版本与上下游边界

## 1. 权威关系

- **导演母版**：镜头审核、视频单元和参考图计划的唯一生产源。
- **底层剧本**：剧情事件、人物关系和台词的一致性对照，不直接驱动下游文件。
- **镜头审核稿**：导演母版的轻量审核视图，不反向成为新的剧情权威。
- **生成计划**：通过后的镜头审核派生产物，不包含最终 Prompt 或平台绑定。

不要建立额外的“变更账本”来增加维护负担。用源路径、版本、审核范围和 SHA-256 解决最重要的问题：源稿变了，旧下游就不能继续用。

## 2. 源哈希规则

两份输出头部至少记录：

```yaml
status: draft | approved | stale_source
source_path: <导演母版路径>
source_version: <从文件或用户输入读取；未知写 unknown>
source_sha256: <64位十六进制>
review_scope: <场次或镜号范围>
generated_at: <ISO 8601 时间>
```

读取旧输出时重新计算当前母版哈希：

- 一致：仅证明该文件内容未变；仍须确认它在当前范围被采用，不能仅凭哈希继续旧计划；
- 不一致：旧输出在语义上立即视为 `stale_source`，即使文件头仍写 approved 也不得下游使用；
- 只有重做受影响审核范围并生成新版本后才能恢复 approved。

不必为了改一个状态而覆盖旧批准文件；新版本记录旧版本已因哪个源哈希变化而失效。

## 3. 版本目录

默认目录：

```text
artifacts/shot-review/<导演稿文件名>/v001/
artifacts/shot-review/<导演稿文件名>/v002/
...
```

选择下一个不存在的 `vNNN`。不得覆盖旧版本。导演稿文件名去掉扩展名，并替换 Windows 不允许的路径字符。

## 4. 修改权限

### 用户发起

用户明确说“把某镜改成……”“直接改母版”时，可以修改其指定源文件。修改后：

1. 重新计算哈希；
2. 重审受影响镜头及相邻接缝；
3. 生成新的审核/生成计划版本；
4. 报告实际修改了哪些源文件。

### AI 发起

AI 判断镜头需要改时，只能先提出最小改动。用户确认前不写源文件。确认后按用户发起流程执行。

### 双源同步

- 景别、角度、运镜、站位、画面细节：只改导演母版。
- 剧情事件、人物关系、台词：若底层剧本已提供，默认同步两份。
- 任一文件缺失或用户限制只改一份：保留另一份为 `待同步`，不得声称两者一致。

## 5. 路由与停点

| 请求 | 负责人 | 本 Skill 行为 |
|---|---|---|
| 用户／项目列式的镜头审核、景别角度、连续性 | shot-reviewer | 执行 |
| 视频生成单元、参考图选择 | shot-reviewer | 审核通过后执行 |
| 导演定调、完整九列表、xlsx | director-master | 转交，不接管 |
| HTML/插件审核台、正式总账、候选回传 | short-drama-production-pipeline / 审核台插件 | 转交，不创建替代页面 |
| 生图/生视频 Prompt | 提示词 Skill | 只交付生成计划 |
| LibTV 连线、编号、节点、运行 | libtv-skill | 只提供语义参考清单 |
| 剧本改编、美术生产、后期剪辑 | 对应专业 Skill | 不触发 |

用户一句话同时包含多个阶段时，只完成本 Skill 范围，并清楚标出下游交接点；不得因为“顺便”而写 Prompt 或运行节点。
